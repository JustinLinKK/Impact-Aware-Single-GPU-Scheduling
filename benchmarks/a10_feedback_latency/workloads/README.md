This package provides TRACE-DERIVED real-image GPU jobs for the A10 feedback-latency pilot. It does not replay historical model-quality scores. The three parent/child chains are constructed for the requestor experiment: sources 17→20 (EfficientNet-B4, 380px), 14→16 (ConvNeXt-Small, 224px), and 22→18 (custom CNN 96px→ConvNeXt-Small 224px). They do not claim recovered historical causal edges. Within a model family, the shortened common training recipe can make distinct source jobs computational replicates; source identity remains distinct.

`candidate.py` directly invokes the actual shared_training.v1 loop. `core.make_workload(spec, output_dir, context=None)` builds the real dataset workload. `core.build_model(spec)` is a CPU-only deterministic model loader. `core.adapter_context`, `core.prediction_metadata`, and `core.expected_signature` expose the exact recipe and source-capture contract without dataset loading. Set `A10_PILOT_SPEC_JSON` to the complete frozen spec, `A10_PILOT_DATA_ROOT` to the staged dataset directory, and `A10_PILOT_OUTPUT` to the job-owned shared-training output directory.

The existing Kaggle-derived 40,960 real TIFF subset is retained. `split.json` freezes 32,768 training IDs, 8,192 heldout IDs, and a disjoint 256-image validation subset (152 negative, 104 positive). Images are byte/SHA-verified at access; missing/corrupt inputs raise. There is no image, AUC, or model fallback. The original source archives are copied under `archived_sources/` with hashes and their prior archive-repair provenance. Recorded archives are never edited.

Each provisional job runs two epochs of 32 successful AdamW updates, seed42, LR1e-4, weight_decay1e-5. The manifest records explicit deviations: deterministic random initialization, IEEE FP32, synchronous shared loop, no cosine LR schedule, shortened budget and batch, common fixed split/validation, and no TTA or competition test/submission. The custom source22 originally used a90/10 split; this pilot uses80/20. Training images may repeat across epochs as specified by the shared loop; validation is never used for parameter updates.

Validation returns finite positive `validation_auc` in[0,1], `validation_bce`, and positive integer class counts. Since the existing shared runner minimizes, checkpoint selection uses `negative_validation_auc`. The selected checkpoint may precede the final update: `selected_model.pt` is the highest-AUC epoch, while `training_state.pt` and the returned result must prove all64 updates. `result.json` is the usable feedback hook; the colocated receipt translates `selected_metric` back to positive AUC and separately exports selected-epoch BCE. The small validation/budget makes this a scheduling experiment, not a claim of competition-ready model quality.

Calibration source8(B0) andsource12(ConvNeXt-Tiny) have disjoint model groups from evaluation. Calibration observations are transfer proxies, not direct measurements of B4/ConvNeXt-Small/customCNN. Input-derived parameter counts support a declared checkpoint/finalization scaling estimate; B4's larger spatial input is an additional transfer limitation. Any budget change must depend only on calibration timings and produce a new immutable manifest before evaluation. No evaluation outcome may tune the recipes.

`manifest.json` binds sources, helper code, split, data identities, parameter counts, predictor/runtime recipe, and expected shared-loop signature. Absolute data/output paths are operational environment only. If budgets or recipe fields change before evaluation, regenerate spec_sha256 using `core.spec_digest`, then expected_runtime_signature using `core.expected_signature`, then freeze the new manifest. Parent scheduler owns cohort clocks, measured profiles, termination, and scoped checkpoint pruning after receipt/update/hash audits.
